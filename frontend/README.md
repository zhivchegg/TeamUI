# TeamUI frontend

Минимальный интерфейс для 1:1 встреч: вход, дашборд, список встреч, заметки и действия.

## Запуск

Нужны Node 20+ и запущенный бэкенд на `http://localhost:8080`.

```bash
npm install
npm run dev        # http://localhost:5173, /api проксируется на бэкенд
npm test           # Vitest
npm run build      # проверка типов и production-сборка
```

## Хранение токенов

- **Access-токен** живёт только в памяти модуля (`src/api/client.ts`). Не пишется в `localStorage` и `sessionStorage`, чтобы его нельзя было прочитать скриптом со страницы. После перезагрузки страницы он восстанавливается через refresh.
- **Refresh-токен** ставит бэкенд в httpOnly-cookie с путём `/api/auth`, `Secure` и `SameSite=Strict`. JavaScript до него не доступен, поэтому кража через XSS его не раскрывает.
- При ответе 401 клиент один раз вызывает `/api/auth/refresh` и повторяет запрос. Бэкенд ротирует refresh-токен, а повторное использование старого отзывает все токены пользователя.

Так компромисс: access-токен в памяти уязвим только на время жизни вкладки, а refresh-токен защищён от чтения скриптами.

## Структура

- `src/api/` — клиент, типы, эндпоинты. Типы повторяют DTO бэкенда (`com.teamui.dto`).
- `src/auth/` — контекст сессии.
- `src/pages/` — экраны.

## Известные ограничения

- В бэкенде нет эндпоинта списка участников и эндпоинта «кто я». Участников берём из `GET /api/dashboard`, `teamHealth.memberCards`.
- Дашборд отдаётся без обёртки `ApiResponse`, а вход и обновление сессии — с ней. Клиент учитывает оба формата.
- Тесты покрывают клиент. Страницы проверены только сборкой и типами, не в браузере.
